# AGENTS.md

HTTPX Limiter is a small, typed Python library (`httpx-limiter` on PyPI) that
provides rate-limited asynchronous transports for
[httpx](https://www.python-httpx.org/) and `httpx2`. It supports Python 3.11 to 3.15.
The core has no required dependencies. Users choose an HTTP integration explicitly
through the `httpx` or `httpx2` extra, and normally also a limiter extra
(`aiolimiter` or `pyrate`), for example `httpx-limiter[httpx2,aiolimiter]`.

## Layout

- `src/httpx_limiter/`: the package.
    - `rate.py`: `Rate`, a validated `(magnitude, duration)` named tuple.
    - `abstract_async_limiter.py`: `AbstractAsyncLimiter`, the limiter interface. A
      limiter is an async context manager that acquires a token on `__aenter__`.
    - `_rate_limiter_repository.py`: `RateLimiterRepository`, the internal
      request-generic base that caches one limiter per identifier. `_types.py`:
      backend-neutral type aliases.
    - `httpx/` and `httpx2/`: the HTTP integrations behind the `httpx` and `httpx2`
      extras. Each exports `AsyncRateLimitedTransport` (one limiter around one inner
      transport), `AsyncMultiRateLimitedTransport` (a limiter per request from a
      repository), `AbstractRateLimiterRepository` (specialized for that client's
      `Request`; subclasses implement `get_identifier(request)` and
      `create(request)`), and `HTTPXAsyncHTTPTransportKeywordArguments` (types the
      keyword arguments forwarded to that client's `AsyncHTTPTransport`). Their
      `__init__.py` raises a `ModuleNotFoundError` that names the extra when the
      client is missing.
    - `aiolimiter/` and `pyrate/`: optional limiter backends behind the `aiolimiter`
      and `pyrate` extras.
    - Import boundaries: only `httpx/` may import `httpx`, only `httpx2/` may import
      `httpx2`, only `aiolimiter/` may import `aiolimiter`, and only `pyrate/` may
      import `pyrate_limiter`. The two HTTP integrations never import each other,
      and the root package, the limiter subpackages, and the internal modules import
      no HTTP client.
- `tests/conftest.py`: the shared `anyio_backend`, `limiter_class` (`aiolimiter` and
  `pyrate`) and `http` (`httpx` and `httpx2`) fixtures. `http` is an `HTTPBackend`
  with the `client` package and the matching `integration` subpackage.
- `test-helpers/`: `httpx_limiter_test_types.py` holds shared test types such as
  `HTTPBackend` and the request and response unions. Pytest's `pythonpath` makes it
  importable until hatch-pip-compile supports Hatch workspaces. Tests import from
  it, never from `conftest`.
- `tests/unit/`: fast tests that use the selected client's `MockTransport`.
    - `test_import_contract.py` blocks HTTP clients through `sys.modules` in fresh
      interpreters and checks what each import loads.
    - `test_typing.py` runs mypy on `tests/typing/`, which the `unit-tests`
      environment installs for it. Cases that must be rejected end in
      `# expect: <mypy-code>`.
- `tests/acceptance/`: tests against real rate-limited HTTP services from
  `compose.yaml`, for both clients.
- `tests/distribution/`: `check_wheel_metadata.py` checks that neither HTTP client is
  required outside its own extra.
- `tests/documentation/`: runs every Python code block in `docs/**/*.md` and
  `README.md` with `mktestdocs`. It awaits each block's `main()` with both clients'
  `AsyncHTTPTransport` mocked.
- `tests/pyodide/`: checks that the wheel works in Pyodide 314.0.7 (host Python 3.14)
  for both clients. CI runs these only in the Pyodide workflow.
- `docs/`: Zensical site (configured in `zensical.toml`, navigation in `.nav.yml`
  files) with a tutorial, how-to guides, API reference (`docs/api.md`, generated by
  mkdocstrings), and architecture decision records in `docs/adr/`.
- `requirements/`: lockfiles generated by hatch-pip-compile, one per hatch
  environment. Do not edit them by hand.

## Design rules

- Transports use composition (see
  `docs/adr/adr001-use-composition-over-inheritance.md`). They subclass only
  their own client's `AsyncBaseTransport`, wrap an injected transport and an
  injected limiter or repository, and delegate `handle_async_request` inside
  `async with limiter`. Do not subclass either client's `AsyncHTTPTransport`.
- The `httpx` and `httpx2` integrations define their classes separately. An
  HTTP-facing feature or fix lands in both. Do not add class factories, automatic
  backend selection, compatibility aliases, or import aliasing. Clients, transports,
  requests, and configuration objects of the two clients are not interchangeable.
- Wrappers forward lifecycle methods. `aclose()` closes the wrapped transport, so
  wrappers that share an inner transport also share its lifetime.
- Constructors take keyword-only, already-built collaborators. Convenience
  construction goes in a `create(...)` classmethod. Examples are
  `httpx_limiter.httpx2.AsyncRateLimitedTransport.create(limiter=...,
  **httpx_transport_kwargs)`, `Rate.create(magnitude, duration)`, and
  `AiolimiterAsyncLimiter.create(rate)`.
- New limiter backends implement `AbstractAsyncLimiter`. New HTTP client support
  follows the integration pattern. Either goes in its own subpackage and gets a
  matching optional dependency in `pyproject.toml`.
- Keep the package pure Python and Pyodide-compatible.
- Public symbols are re-exported from `__init__.py` with redundant aliases
  (`from .rate import Rate as Rate`) so type checkers treat them as public. The root
  package exports only `Rate`, `Number`, and `AbstractAsyncLimiter`. The HTTP
  classes are exported by `httpx_limiter.httpx` and `httpx_limiter.httpx2`, and the
  limiters by `httpx_limiter.aiolimiter` and `httpx_limiter.pyrate`. In the HTTP
  integrations, the guarded client import must stay above the submodule imports so
  that a missing client raises the focused error. Re-raise `ModuleNotFoundError`
  for any other missing module. When you add a public symbol, also list it in the
  section for its subpackage in `docs/api.md`.

## Code style

- Ruff with `select = ["ALL"]` and an 88-character line length. Use
  `# noqa: <CODE>` only with a specific rule code and only when the rule truly does
  not apply.
- Google-style docstrings checked by pydoclint. Multi-line docstrings start on the
  line after the opening quotes, and a blank line comes before the closing quotes.
  Document constructor arguments in the class docstring, not in `__init__`. Do not
  repeat types in docstrings.
- Every source and test file starts with the Apache-2.0 license header, using the
  year the file was created, followed by two blank lines and a module docstring.
- Use `from __future__ import annotations`. Put imports needed only for typing under
  `if TYPE_CHECKING:  # pragma: no cover`. Leave two blank lines after the imports.
- Define immutable value objects as `typing.NamedTuple` subclasses, like `Rate`, in
  source and test code. Do not use frozen dataclasses.
- The code must pass mypy, ty, and pyrefly.

## Tests

- Async tests use `@pytest.mark.anyio`. The `anyio_backend` fixture in
  `tests/conftest.py` selects asyncio.
- Use the `http` fixture for tests that need an HTTP client, and cross it with the
  `limiter_class` fixture when behavior should hold for any limiter
  (`AiolimiterAsyncLimiter` and `PyrateAsyncLimiter`). The fixtures import lazily, so
  a missing client fails the tests instead of skipping them. Create repository
  classes and instances inside the test for the selected client, and keep
  backend-independent tests, such as `Rate` and limiter algorithms, unparametrized.
- Build mock responses with the selected client's `MockTransport`. Do not use
  `pytest-httpx`.
- Add typing examples to `tests/typing/`: accepted ones to the module of the
  matching client and mixed-client ones to `rejected.py` with `# expect: <code>`.
- Acceptance tests need the `compose.yaml` stack running (`docker compose up -d`). A
  Traefik gateway serves `http://httpbin.localhost` limited to an average of 20
  requests per second, and `http://fast.localhost` limited to 40 requests per
  second.
- Each code block in the docs and README must run on its own and restate its
  imports, because the documentation tests run every block independently. Give
  runnable blocks an async `main()`. On the documentation site, show each example
  for both clients in `=== "HTTPX"` / `=== "HTTPX2"` tabs. The README shows HTTPX
  examples only, explains the HTTPX2 differences in prose, and keeps one example
  that uses both clients together.

## Commands

The project uses [hatch](https://hatch.pypa.io/) 1.16 or newer, because it relies on
PEP 735 dependency groups. These are the checks CI runs:

```shell
hatch run style:check                      # pydoclint + ruff check
hatch run style:format                     # ruff format
hatch run style:fix                        # ruff check --fix
hatch run types:check                      # mypy, ty, pyrefly
hatch run +py=3.15 unit-tests:run          # incl. import contract + typing
hatch run +py=3.15 acceptance-tests:run    # needs the compose stack
hatch run +py=3.15 documentation-tests:run
hatch run docs:build                       # zensical build --strict
hatch run distribution:check               # build + twine check + wheel extras check
hatch run audit:check                      # pip-audit
hatch run workflows:check                  # zizmor, pinned in pyproject.toml
```

The zizmor workflow runs only on pull requests to `main` that change
`.github/workflows/`.

CI runs unit tests on Python 3.11 and 3.15 on Linux, macOS, and Windows. Pass
arguments to pytest after `--`, for example
`hatch run +py=3.15 unit-tests:run -- -k multi`.

Running hatch may rewrite the headers of `requirements/*.txt`. Do not commit those
changes unless the task is to update dependencies.

## Changes and releases

- Add a user-facing entry under `## [Unreleased]` in `CHANGELOG.md` (Keep a
  Changelog format) for every change in behavior, API, or supported versions.
- Use Conventional Commit messages (`fix: ...`, `feat: ...`, `docs: ...`) and
  `fix/...` or `feat/...` branch names.
- Record significant design decisions as ADRs in `docs/adr/` with the `adr` skill,
  and link them in `docs/adr/index.md`.
- Versions come from git tags through hatch-vcs. Never edit the generated
  `src/httpx_limiter/_version.py`. Pushing a tag such as `1.2.3` publishes to PyPI
  and deploys the `stable` docs, so do not create or push tags unless asked.
