# AGENTS.md

HTTPX Limiter is a small, typed Python library (`httpx-limiter` on PyPI) that
provides rate-limited asynchronous transports for [httpx](https://www.python-httpx.org/).
It supports Python 3.11 to 3.15 and has `httpx` as its only required dependency.

## Layout

- `src/httpx_limiter/`: the package.
    - `rate.py`: `Rate`, a validated `(magnitude, duration)` named tuple.
    - `abstract_async_limiter.py`: `AbstractAsyncLimiter`, the limiter interface. A
      limiter is an async context manager that acquires a token on `__aenter__`.
    - `async_rate_limited_transport.py`: `AsyncRateLimitedTransport`, which wraps
      one limiter around one inner transport.
    - `abstract_rate_limiter_repository.py`: `AbstractRateLimiterRepository`.
      Subclasses implement `get_identifier(request)` and `create(request)`. `get`
      caches one limiter per identifier.
    - `async_multi_rate_limited_transport.py`: `AsyncMultiRateLimitedTransport`,
      which picks a limiter per request from a repository.
    - `types.py`: `HTTPXAsyncHTTPTransportKeywordArguments`, which types the
      keyword arguments forwarded to `httpx.AsyncHTTPTransport`.
    - `aiolimiter/` and `pyrate/`: optional limiter backends behind the `aiolimiter`
      and `pyrate` extras. Only these subpackages may import `aiolimiter` or
      `pyrate_limiter`.
- `tests/unit/`: fast tests that use `httpx.MockTransport` or `pytest-httpx`.
- `tests/acceptance/`: tests against real rate-limited HTTP services from
  `compose.yaml`.
- `tests/documentation/`: runs every Python code block in `docs/**/*.md` and
  `README.md` with `mktestdocs`.
- `tests/pyodide/`: checks that the wheel works in Pyodide. CI runs these only in the
  Pyodide workflow.
- `docs/`: MkDocs Material site with a tutorial, how-to guides, API reference
  (`docs/api.md`, generated by mkdocstrings), and architecture decision records in
  `docs/adr/`.
- `requirements/`: lockfiles generated by hatch-pip-compile, one per hatch
  environment. Do not edit them by hand.

## Design rules

- Transports use composition (see
  `docs/adr/adr001-use-composition-over-inheritance.md`). They subclass only
  `httpx.AsyncBaseTransport`, wrap an injected transport and an injected limiter
  or repository, and delegate `handle_async_request` inside `async with limiter`.
  Do not subclass `httpx.AsyncHTTPTransport`.
- Wrappers forward lifecycle methods. `aclose()` closes the wrapped transport, so
  wrappers that share an inner transport also share its lifetime.
- Constructors take keyword-only, already-built collaborators. Convenience
  construction goes in a `create(...)` classmethod. Examples are
  `AsyncRateLimitedTransport.create(limiter=..., **httpx_transport_kwargs)`,
  `Rate.create(magnitude, duration)`, and `AiolimiterAsyncLimiter.create(rate)`.
- New limiter backends implement `AbstractAsyncLimiter`, go in their own
  subpackage, and get a matching optional dependency in `pyproject.toml`.
- Keep the package pure Python and Pyodide-compatible.
- Public symbols are re-exported from `__init__.py` with redundant aliases
  (`from .rate import Rate as Rate`) so type checkers treat them as public. The import
  order in `src/httpx_limiter/__init__.py` matters because backends import from the
  top-level package, so do not let a formatter re-sort it. When you add a public
  symbol, also list it in `docs/api.md`.

## Code style

- Ruff with `select = ["ALL"]` and an 88-character line length. Use
  `# noqa: <CODE>` only with a specific rule code and only when the rule truly does
  not apply.
- Google-style docstrings checked by pydoclint. Multi-line docstrings start on the
  line after the opening quotes, and a blank line comes before the closing quotes.
  Document constructor arguments in the class docstring, not in `__init__`. Do not
  repeat types in docstrings.
- Every source and test file starts with the Apache-2.0 license header, using the
  year the file was created, followed by two blank lines and a module docstring.
- Use `from __future__ import annotations`. Put imports needed only for typing under
  `if TYPE_CHECKING:  # pragma: no cover`. Leave two blank lines after the imports.
- The code must pass mypy, ty, and pyrefly.

## Tests

- Async tests use `@pytest.mark.anyio`. The `anyio_backend` fixture in each
  `conftest.py` selects asyncio.
- Parametrize over both backends (`AiolimiterAsyncLimiter` and `PyrateAsyncLimiter`)
  when behavior should hold for any limiter.
- Acceptance tests need the `compose.yaml` stack running (`docker compose up -d`). A
  Traefik gateway serves `http://httpbin.localhost` limited to an average of 20
  requests per second, and `http://fast.localhost` limited to 40 requests per
  second.
- Each code block in the docs and README must run on its own and restate its
  imports, because the documentation tests run every block independently.

## Commands

The project uses [hatch](https://hatch.pypa.io/) 1.16 or newer, because it relies on
PEP 735 dependency groups. These are the checks CI runs:

```shell
hatch run style:check                      # pydoclint + ruff check
hatch run style:format                     # ruff format
hatch run style:fix                        # ruff check --fix
hatch run types:check                      # mypy, ty, pyrefly
hatch run +py=3.15 unit-tests:run
hatch run +py=3.15 acceptance-tests:run    # needs the compose stack
hatch run +py=3.15 documentation-tests:run
hatch run docs:build                       # mkdocs build --strict
hatch run distribution:check               # build + twine check
hatch run audit:check                      # pip-audit
```

CI runs unit tests on Python 3.11 and 3.15 on Linux, macOS, and Windows. Pass
arguments to pytest after `--`, for example
`hatch run +py=3.15 unit-tests:run -- -k multi`.

Running hatch may rewrite the headers of `requirements/*.txt`. Do not commit those
changes unless the task is to update dependencies.

## Changes and releases

- Add a user-facing entry under `## [Unreleased]` in `CHANGELOG.md` (Keep a
  Changelog format) for every change in behavior, API, or supported versions.
- Use Conventional Commit messages (`fix: ...`, `feat: ...`, `docs: ...`) and
  `fix/...` or `feat/...` branch names.
- Record significant design decisions as ADRs in `docs/adr/` with the `adr` skill,
  and link them in `docs/adr/index.md`.
- Versions come from git tags through hatch-vcs. Never edit the generated
  `src/httpx_limiter/_version.py`. Pushing a tag such as `1.2.3` publishes to PyPI
  and deploys the `stable` docs, so do not create or push tags unless asked.
